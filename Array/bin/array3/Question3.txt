
## ✅ **WHY we write `int max = arr[i][0];` (Very Important)**

### 🔹 Reason 1: We need a starting value

• To compare numbers, Java needs an **initial value**
• `arr[i][0]` is the **first element of the current row**
• It is guaranteed to belong to that row ✅

---

### 🔹 Reason 2: Correct for ANY data (even negatives)

❌ Wrong approach:

```java
int max = 0;   // ❌ fails if row has negative numbers
```

✅ Correct approach:

```java
int max = arr[i][0];   // ✅ always correct
```

Example:

```java
{-5, -2, -10}
```

• If `max = 0` → wrong
• If `max = -5` → correct

---

### 🔹 Reason 3: Row-wise logic

• Each row has **different values**
• So each row needs a **fresh max**
• `arr[i][0]` ensures max belongs to that specific row

---

## ✅ Step-by-step for first row

Row = `10 60 30`

| Step    | Value       | max |
| ------- | ----------- | --- |
| Start   | `arr[i][0]` | 10  |
| Compare | 60          | 60  |
| Compare | 30          | 60  |

✅ Final max = **60**

---

## ✅ Interview-ready explanation (short)

> We initialize `max` with the first element of the row to ensure correct comparison for all values, including negative numbers, and to reset max for each row independently.

---

### ✅ **Why we write this line**

```java
if (arr[i][j] > max) {
    max = arr[i][j];
}
```

## ✅ Simple Meaning (Plain English)

• We are **checking each number** in the row
• We **compare** the current number with the stored `max`
• If the current number is **bigger**, we **update `max`**

👉 This is how we **find the largest value**

---

## ✅ What happens if we REMOVE this `if`?

❌ `max` will **never change**
❌ You will always get the **first element** as answer
❌ No comparison = no maximum finding

---

## ✅ Step-by-Step Example

Row:

```
10 60 30
```

### Initialization

```java
int max = 10;
```

### Loop execution

| arr[i][j] | Condition | max |
| --------- | --------- | --- |
| 10        | 10 > 10 ❌ | 10  |
| 60        | 60 > 10 ✅ | 60  |
| 30        | 30 > 60 ❌ | 60  |

✅ Final max = **60**

---

## ✅ Why `>` (greater than) is used

• We want the **largest value**
• If number is **greater**, replace old max
• Smaller values are ignored

---

## ✅ Real-Life Analogy 🧠

• Imagine finding the **tallest person** in a line
• You compare each person’s height
• If someone is taller → update tallest
• Same logic here ✅

---

## ✅ Important Rule (Interview GOLD)

> To find a maximum, you must **compare and update**

---

## ✅ Common Mistakes

❌ Forgetting this `if`
❌ Using `<` instead of `>`
❌ Writing comparison outside the loop

---

## ✅ One-Line Explanation (Interview Ready)

> This condition checks whether the current element is larger than the stored maximum and updates it to always keep the largest value found so far.
